# Evaluation tasks

There are ten tasks for the baseline vs Code Atlas comparison, plus the `t00-smoke` harness check. The format is described in `../README.md`. `VERIFICATION.md` shows, for every task, the hidden tests failing at base and passing with `reference.patch`.

- **Self tasks** (`repo = "self"`) run on this repository at the frozen base `327f4dc99bfcab783d882d8fa39f5b7eb2bbb22f`.
- **External tasks** run on `honojs/hono` at `f23b146afcec63606144cde50b5fbd360dd60238`, a TypeScript pnpm workspace: core `hono` plus the `adapters/*` packages. Each external task uses `setup = ["npx --yes pnpm@12.6.0 install --frozen-lockfile --prefer-offline"]`. That install is the only networked step; once the pnpm store and npx cache are warm it takes 1–2 s per tree.

## Conventions

- **Hidden tests** are always new files, because a hidden test's destination is stripped from the tree. Validation may also run existing tests that the agent is expected to update (t05, t08).
- **Refactor (t04):** its hidden test pins today's behaviour and passes at base. The task discriminates through a structural check in `commands`, which the prompt states as a requirement. No hidden test can check that the four gates go through *one* shared helper without fixing that helper's name or location, which the prompt deliberately leaves open. A solution that moves the four snippets into four separate helpers outside `detectors/` passes validation; only the judge catches "moved but not shared". `forbidden_duplicates` is empty because the reference itself adds a shared function named like the old `FileView::ts_specifiers`, which would otherwise be flagged.
- **Planted bug (t03):** it lives only in `t03-nested-router-links/base.patch`. The harness applies it to the archived tree before the `eval-base` commit, so it never enters the repository's history. `reference.patch` is relative to the patched base.
- **Ground truth:** `relevant_files`, `must_change`, `must_consider`, `reuse_targets` and `forbidden_duplicates` come from manual reading of the code and from the reference solutions, never from Code Atlas output.
- **Regression commands:** they name test targets explicitly whenever a package has a hidden test, so the base check measures only existing tests. Self trees keep `fixtures/**/expected.toml`, so atlas-query, atlas-detect `coverage` and atlas-link `fixtures`/`incremental` run as regression wherever a task touches those crates.
- **pnpm in external tasks:** the corepack `pnpm` shim on the authoring machine cannot run hono's pinned pnpm 12.6.0. The external prompts include an environment note pointing to `npx pnpm@12.6.0` and `./node_modules/.bin`, so both conditions get the same hint.
