# atlas-ide

`IdeService`: exact read operations over language servers (references, declaration, implementations, outline, diagnostics) plus graph extras, exact edits (`src/edit`: rename, symbol edits, safe delete, text edits, plans), and pass-throughs to the graph modes (`find`, `hierarchy`, `source = graph` outline and references). Shared by CLI and MCP.

## Service

- One `IdeService` per (process, project). It owns its `QueryEngine` (built from the shared `Arc<Engine>`), one `LspPool` (`IdeMode::Warm` for MCP, `IdeMode::OneShot` for CLI) and a `Launcher`.
- `reload(project)` adopts new `lsp` settings: a changed pool configuration (or disabling) replaces the pool and shuts the old one down; the discovery cache is cleared either way. Units whose configuration changed are replaced by the pool on their next use. Callers still call `Engine::reload_project` themselves.
- `shutdown()` (also on drop) shuts every server down; MCP must call it before `persist_similarity`.
- `lsp.exclude` (repo-relative globs, `IdeSettings::exclude`) drops matching Cargo projects from rust-analyzer's `linkedProjects` and makes files under them `NotCovered`. TypeScript workspace folders are repo roots, so for TypeScript it only refuses files. A rust-analyzer that reports `health = error` still answers reads, but every answer is `Partial` with its message (code-atlas cannot tell which file belongs to a failing project); edits refuse.
- Discovery sits behind `Launcher`: `DiscoveryLauncher` (production, atlas-lsp discovery + `atlas_scip::locate_rust_analyzer`) or a test launcher. Successful launch specs are cached per (kind, scope, folders); failures are not, so an install is picked up on the next call.
- `check_servers()` (CLI `lsp check`) runs the barrier, then for every language unit (one per repo with `lsp.unit = repo`) plans it, spawns it once, waits `check_timeout_secs` for readiness and retires it. It reports readiness time, server and TypeScript versions and `Lease::health_error()` per unit; a failing unit is a `Failed` entry, not an error.

## Exact operations

- Order is fixed: barrier (`QueryEngine::fresh`) → target resolution → unit plan (`Engine::language_units()`, taken before the unit lock) → per-unit mutex → `pool.sync` (one lease for sync and request) → requests. Reads use `SyncDemand::Best`; rename and safe_delete use `SyncDemand::Exact`.
- Lock order: the per-unit mutex may be held while the engine mutex is taken (a barrier, `write_then_refresh`), never the reverse. Store reads use the read-connection pool and take neither. Nothing called with the engine mutex held may take a unit lock.
- Answers are never written to the store. They carry `ServerView`: server, version (reported by the server, discovery's value only as fallback), reported TypeScript version, certainty `compiler_verified` / `[compiler]` with `source = "lsp:<server> <version>"`, completeness, caveats and warnings.
- Never present a partial answer as complete: `Settle::Busy`, a lost document sync, unsettled diagnostics and an incomplete flycheck make the answer `Partial` (rendered `PARTIAL: …`). `Settle::Unconfirmed` is a caveat naming the paths; drift, skipped overlays, restarts and rewritten `Cargo.lock` files are warnings.
- No fallback: disabled or unavailable servers are typed errors (`Disabled`, `Unavailable`, `ServerFailed` for spawn, crash-loop, readiness and pool failures) with the install hint; outline (when `source = lsp` is asked for) and references add "retry with source='graph'". Graph answers for references are only returned when `source = graph` is asked for, and keep their tags. Outline defaults to `source = graph` (no server is started): its header says it is syntactic and from the index, a file without graph facts is an explicit not-found that suggests `source = lsp`, a failed parse says `NO FACTS`, a partial parse says `PARTIAL`; `source = lsp` stays explicit and never falls back.
- A TypeScript server that reports TypeScript ≥ 7 is retired and the call fails `Unavailable`; that unit refuses without spawning for 60 s. A reported version that contradicts a workspace tsserver choice is a warning.
- Change sets for sync come from the run ledger (`barrier`/`index`/`edit` runs between the server's generation and the target). Any gap (missing run, failed or running run, capped section, more than 256 runs) is `ChangeList::Unknown`, which restarts the server. A non-empty `graphs_changed` in range for a repo among the unit's folders adds a caveat. Manifests (`package.json`, `tsconfig*.json`, `jsconfig*.json`, `Cargo.toml`, `Cargo.lock`, `build.rs`, `.cargo/config*`) in the unit roots, Cargo directories and every package directory (a directory of indexed files holding `package.json` or `Cargo.toml`, recomputed per generation) are compared against a per-server snapshot over the union of the old and new directory sets (manifests of a new directory count as changed, those of a vanished one as deleted), because the ledger does not list manifest edits.

## Targets and positions

- Targets: key or id, `[repo:]path:LINE:COL` (1-based, UTF-8 byte column), `[repo:]path:LINE`, name paths. Endpoints, files and non-code entities are refused with typed errors; paths outside every repo root (after canonicalisation) are `OutsideProject`. A TypeScript overload set (keys equal up to `~n`) is queried at its first signature; anything else ambiguous is `Targeted::Ambiguous`.
- A symbol position is its declared name token. The indexed hash is read before and after `name_span`; if it moved, the barrier runs once and resolution repeats, then `SourceChanged`. The anchor text must hash to that indexed value, and the server's open document must hash to the anchor text, or the call fails `SourceChanged`.
- Every LSP position is converted with `LineIndex` over text proven to be what the server saw: the open overlay's hash, or for unopened files the indexed hash. A site in a file that changed, cannot be read or does not fit the position keeps the server's line, no column, and an `unverified` reason. Displayed columns are 1-based UTF-8 byte columns on `\n`-counted lines.
- Enclosing symbols come from the graph (`innermost_symbol`) only when the file's text equals the indexed text; otherwise from the server's document symbols.

## References extras

- `outside the language server's view` lists, for symbol targets only, inbound graph usages the server did not return (matched by repo, path, line and column, line only when the graph has no column): other repos, mock references (`mock` attr), and same-repo sites with authoritative certainty (`not in the server's project`, e.g. files outside the tsconfig `include`). Unreturned heuristic same-repo sites are counted in a caveat, not listed. Unresolved same-name sites are tagged `[unresolved]`. HTTP consumers (`calls_endpoint`, inferred links excluded) of endpoints the target exposes are listed once per client call site (evidence noted `endpoint` is skipped). Each keeps its graph certainty tag.
- A position target's own site is kept; only a symbol target's declaration is dropped from the server's list.

## Diagnostics

- Pull (`textDocument/diagnostic`) when advertised; otherwise TypeScript documents are closed (waiting up to 1 s for the clearing publish) and reopened, because typescript-language-server 5.x never republishes an empty result for a file it already reported empty; after a reopen it publishes syntax diagnostics before semantic ones, so the result settles only after two publishes and 300 ms of quiet, or one publish and 1.5 s of quiet. Other servers get the open document re-sent under a new version (`Lease::touch_document`) and the latest publish with `version >= v` (or no version) after that point wins once 300 ms pass without a newer one, at most 10 s. A timeout, with or without a publish, is `Partial`; without one the answer says nothing is known and never reports a clean file. A quiet window cut short by the deadline is a timeout, not settled.
- rust-analyzer: `rust-analyzer/runFlycheck` (works with checkOnSave off), begin within 5 s or `not_run`, end within `check_timeout_secs` or `timed_out`. Unless complete, the answer is `Partial` and only `source = "rust-analyzer"` diagnostics are kept, so earlier cargo check results never pass as current.
- TS2307 adds the caveat that references through the unresolved module are invisible to exact operations.

## Edits (`src/edit`)

- One entry point, `IdeService::edit(&EditRequest)` for `rename`, `replace_body`, `insert_before`, `insert_after`, `safe_delete`, `replace_content`, `replace_in_files` and `apply { plan_id }`, plus `apply_plan(IdePlan)` and `planned(id)` for plan files. Every call returns `Response<EditOutcome>`: freshness header, server versions, files with before/after hashes and hunks, and a status `applied | dry_run | refused | rolled_back | partially_applied`. Refusals and failed writes are outcomes; `IdeError` is left for invalid requests, unknown or expired plans, and unavailable or disabled servers. Rename and safe_delete never run without a server.
- Flow and lock order: IDE edit mutex (one edit per process, dry runs included) → barrier → target resolution → unit plan → unit mutex (several only for text edits, rust-analyzer before TypeScript, all under the edit mutex) → `pool.sync` → LSP requests → plan → (dry run: cache, stop) → diagnostics baseline → `Engine::write_then_refresh(files, || atlas_edit::apply)` (engine mutex → index lock → `<db>.edit.lock` inside the closure) → resync at the new generation (`didChange`/`didOpen`, watched-file events) → overlay check → diagnostics delta. The unit mutex stays held across `write_then_refresh`, so no read in this process syncs that server between planning and notifying; nothing under the engine mutex takes a unit lock.
- TypeScript results depend on which tsconfig projects tsserver has loaded, and a solution-style `tsconfig.json` loads a project only when one of its files is opened. Rename, safe_delete and exact references therefore open, in the same sync, the anchor; every file of the graph's candidate sites (target, overload members and, for rename, the implements family) in the server's language and unit, at most 200; and one representative file (preferably one no other selected project includes) of every `tsconfig*.json`/`jsconfig*.json` project in the anchor's repo whose `files`/`include`/`exclude` (one relative `extends` level; patterns joined to the config directory and normalised, so `../` works) contain the anchor, plus projects that `references` one of those, at most 16. A config that cannot be parsed is never dropped silently: a caveat names it and a file from its directory is opened; if there is none, it is listed as unloaded, and rename apply (like `UNVERIFIED`) refuses unless `allow_unverified`, while safe_delete refuses. Beyond either bound a caveat says so. They wait for readiness before asking. Guarantee, and no more: for projects in the anchor's repo that contain the anchor file, the plan does not depend on earlier reads; projects elsewhere that only import the anchor's package are not loaded.
- Rename uses `SyncDemand::Exact` and refuses on a partial view, which includes a rust-analyzer `health = error`: `SyncIncomplete` (rust-analyzer busy, TypeScript still unconfirmed after the restart), `Settle::Busy`, lost sync or drift, also after the retry resync.
  - `prepareRename` must return a range that contains the name position and reads the entity name (or `r#name`), else `server and index disagree at <loc>`; a server error or `null` is a refusal.
  - `WorkspaceEdit` conversion: `changes` or `documentChanges` in order; text edits to a rename destination map back to the source, edits after a rename away are refused; `CreateFile`/`DeleteFile` and overwriting renames are refused; `requires_confirmation` is refused; every path goes through `EditScope` and one refusal refuses the rename, listing every file.
  - Per file: an open document must hash to the disk text and match every edit version; an unopened one must hash to the indexed text. Ranges convert with `offsets_strict`. Each edit must replace `old`, `r#old`, or insert next to `old`; its text must contain the new name and no line break. A failure re-syncs every file of the edit as an overlay and asks once more, then refuses. Overlapping or out-of-bounds edits are refused, and so is a plan that does not change the target's own name.
- "Not renamed, verify" comes from the graph references of the target and its `Implemented` family (inbound sites and implementing declarations), unresolved same-name sites (`Dynamic`) and HTTP consumers (`Http`). A site is listed when no plan edit covers its name token (its line when the graph has no column). Reason precedence: `Mock` (mock attr), `TokenMismatch` (no column), `OutsideLanguageServer` (another repo or an authoritative edge), `Heuristic`.
- Same-repo authoritative sites the server did not rename are `unverified`: a dry run lists them under `UNVERIFIED:` and applying the plan refuses unless the rename was made with `allow_unverified`. Sites that reach the symbol through an alias the server kept are listed with `via kept alias …` and are not unverified. Rename also refuses when the graph has a symbol of the new name in the same scope (same parent item path in the same module), and, for non-member symbols only, when an edited file binds the new name (imports and declarations, matched on code with comments and strings blanked) inside a brace block that contains one of the rename's edits (module level contains all).
- Overload sets (keys equal up to `~n`) contribute every member's graph sites. `replace_body`, `insert_*` and `safe_delete` refuse on an overload member rather than edit one signature. safe_delete counts a heuristic site as a blocker when its file is not open in the server.
- `cross_repo: apply` edits a listed site only if it is `OutsideLanguageServer`, authoritative, in scope, in a file whose disk hash equals the indexed hash, and its token reads the old name on identifier boundaries; never a re-export, a shorthand property or a property key. It is all or nothing per file: every whole-word occurrence of the old name there must be covered. When the server keeps the old name as an alias (an edit whose text is not the new name but still contains the old name, such as TypeScript's `export { new as old }`), a caveat names it, and graph sites in files that import the old name through it (a relative import resolving to an aliasing file, any package import, any non-TypeScript file) are not applied, because they keep compiling.
- `IdePlan.version` (`PLAN_VERSION`, 1) is serialized; a missing (0) or different version, or a plan of another project, is a `Refused` outcome. `IdeService::close_writes()` closes the write gate unless `write_then_refresh` is running (then it returns false); once closed, edits fail `Interrupted` before writing. CLI signal handlers use it so a process never exits mid-write. `EditView` renders an outcome with a caller-supplied dry-run plan note.
- Plans are `Serialize + Deserialize` (`IdePlan`), cached in process (32 plans, `IdeOptions::plan_ttl` 15 min), and consumed by `apply`. Rename and safe_delete plans carry `PlanGuard::Project { run }` and are refused when the run ledger lists any changed file since that run, checked again by a barrier immediately before `write_then_refresh`; symbol and text plans rely on atlas-edit's expected hashes (`Stale`, nothing written).
- Symbol edits: the graph span and the name span are bound to the indexed hash. A TypeScript declarator span (`const`/`let`/`var`) is widened to its statement (`export`/`declare` modifiers, also on the previous line, through a trailing `;`) when it is the statement's only declarator; a declarator sharing its statement, a destructuring pattern, or any other symbol whose span overlaps the declaration without nesting refuses. `replace_body` on a widened statement refuses unless the new text restates the keywords (`export const …`), and any `replace_body` whose text starts with declaration keywords the span lacks refuses. `floor` is the later of the previous sibling's end inside the same parent and the parent's name end (file start at top level). A warm server (never spawned for this) cross-checks `documentSymbol`: the innermost symbol whose selection range holds the name must start within the leading region and end at the span end, give or take whitespace, `;` or `,`; anything else refuses. `replace_body`/`insert_*` run without a server; `safe_delete` needs one: blockers are LSP references outside the removed range plus every graph site the server did not return except heuristic ones; any blocker refuses with the full list.
- Text edits are atlas-edit's; `replace_in_files` without `occurrences` or `expected_count` is a dry run (`needs_selection`) whose plan id can still be applied.
- Warm servers for symbol and text edits are reached through `LspPool::live`/`sync_live`: nothing is spawned or restarted for them, and a failure skips the cross-check with a caveat.
- After a write: only servers that took part (or were warm) are told; up to 20 edited files per server, pull or touch-and-wait with one 10 s deadline per phase, native diagnostics only. New errors are the after-errors not matched by (code, message) in the baseline; files without a settled baseline and result are listed under `PARTIAL`, never reported clean. The text says "no new errors in the N edited file(s)", or "in the C checked file(s) (U of N edited files not checked)" beyond the 20-file cap, and "native errors … cargo check not run" when rust-analyzer took part; it never claims a clean project. A server that does not hold the written hash is a warning.
- Failures: `RolledBack` renders a `FAILED:` first line, `PartiallyApplied` a `DEGRADED:` first line with the files still changed and the rollback errors; the server is re-synced and `write_then_refresh` re-indexes in every case.
- `IdeOptions::diagnostics_timeout` (10 s) bounds each diagnostics phase; tests under load may raise it.
- `REPLACE_BODY_NOTE`, `REGEX_NOTE` and `REPLACE_IN_FILES_NOTE` are appended to the `atlas_edit` description by `atlas-mcp`; keep their meaning in sync with `docs/agent-integration.md`.

## Testing

- The fake server is `atlas-test-lsp`'s `atlas-fake-lsp`, located with `atlas_test_lsp::fake_lsp_path()` (dev-dependency only, so release builds never contain it).
- Real-server tests (`tests/lsp_real.rs`, `tests/edit_real.rs`, `tests/golden_rename.rs` with exact `repo:path:line:col` site lists) run with `ATLAS_TEST_TS_LSP`, a server on PATH or in the npx cache, and rust-analyzer on PATH or via rustup; otherwise they print `SKIPPED`. They never download and only edit fixture copies.
- `tests/edit_fake.rs` drives edits through the fake server (`canned` answers are fixed per method, so a retry sees the same edit); `tests/edit_concurrency.rs` checks the edit mutex and that a barrier from a second `Engine` never indexes half of a rename.
