# atlas-edit

Edit plans, path-guarded atomic application with rollback, text operations and symbol regions. No LSP and no engine dependency; `atlas-ide` (B7) converts `WorkspaceEdit`s into `EditPlan`s and calls `apply` inside `Engine::write_then_refresh`.

## Contracts

- `apply` writes plan text verbatim. Planners convert agent text to the file's dominant line ending with `LineEnding::normalize` before it enters a plan; this crate's text and symbol planners already do, and every other caller (LSP edits included) must decide explicitly. A dry-run diff is therefore exactly what gets written.
- Plan offsets are byte offsets into the raw file, BOM included; no edit may touch the BOM, and edited files must be UTF-8.
- Every path goes through `EditScope`: canonical parent and leaf (case aliases resolve to the on-disk name), registered repo root, no symlinked leaf, no `.git`/`.hg`/`.svn`/`.jj` segment (any case), no default-excluded directory unless the repo include re-admits it, not gitignored (a file under an ignored directory cannot be re-included), no `\` in names. One refused file refuses the whole plan.
- Read-only files (no write bit) are refused (`ReadOnly`) for content edits, rename sources and deletes.
- `replace_body` treats the lines above the declaration's code (the leading region plus any attribute or decorator lines inside the span, which TS spans start at) as two groups: doc lines (`///`, `/** */`, `#[doc = …]`) and attribute lines (`#[…]`, `@decorator`, including ones written on the declaration line). New text that restates any doc line replaces the whole doc group; new text that restates any attribute replaces the whole attribute group; a group the new text does not restate is kept verbatim. Plain comments are never removed, and a plain comment the new text repeats is not duplicated. New text that brings only a plain comment or a bare body replaces the code from its first non-attribute token.
- Regex patterns are multi-line, CRLF-aware and `.` matches newlines (Serena-compatible): tool descriptions should say "`.` matches newlines; use `.*?` or `[^\n]*` for single-line matches". Replacements use `$1`/`${name}`; a reference to a group the pattern does not define is refused (`$1_bar` means group `1_bar`: write `${1}_bar`; `$$` is a literal `$`). Literal multi-line patterns match the file's line ending.

## Residual risks

- Hash TOCTOU: every content file, rename source and delete target is re-hashed immediately before its rename or unlink. An external writer that does not take `<db>.edit.lock` can still slip in between that check and the rename (a microsecond window).
- Metadata: a content commit writes a new file and renames it over the old one. Permissions are copied; extended attributes, ownership, ACLs and SELinux labels are not, and hard links to the old file are detached (they keep the old content). Detaching is deliberate: editing through one link must not change files outside the repo.
- No-replace moves use `renameat2(RENAME_NOREPLACE)`/`renameatx_np(RENAME_EXCL)`, then hard link + unlink. Filesystems that support neither (exFAT, some FUSE mounts) fall back to check-absent + `rename` under the edit lock, which a writer outside the lock could race.
- Temp files are named `.atlas-edit.<lock id>.*`, where the id is derived from the canonical edit-lock path, so a sweep only removes temps created under its own lock. The same repo registered in two projects has two edit locks: those projects must not edit it concurrently, or one project's apply can see the other's write as a stale file and roll back.
- Crashes: there is no journal. A process killed mid-commit leaves a mix of committed and original files, plus `.atlas-edit.<lock id>.*` temp files holding the new content of files it did not reach. The next `apply` sweeps stale temps in the directories it touches (only lock holders create temps, so under the lock every existing one is stale) and lists them in `ApplyReport::swept`; `sweep_stale_temps` sweeps the whole project.
